## 快速参考卡

### 最常用的 10 条命令

```bash
# 工作目录
cd ~/erpnext/frappe_docker

docker compose ps                              # 1. 查看所有服务状态
docker compose logs -f --tail=100 backend      # 2. 看 backend 日志
docker compose up -d                           # 3. 启动
docker compose stop                            # 4. 暂停
docker compose restart backend                 # 5. 重启某个服务
docker compose exec backend bench doctor       # 6. 健康检查
docker compose exec backend bench migrate      # 7. 数据库迁移
bash ~/erpnext/backup.sh                       # 8. 手动备份
bash ~/erpnext/monitor.sh                      # 9. 系统总览
df -h                                          # 10. 看磁盘空间
```

### 容器状态解读

```bash
docker compose ps
```

输出中 `STATUS` 列：

| 状态 | 含义 | 怎么办 |
|------|------|--------|
| `Up 3 days` | 正常运行 3 天了 | ✅ 正常 |
| `Up About a minute` | 刚启动不久 | ✅ 正常 |
| `Up X minutes (unhealthy)` | 健康检查失败 | 看日志排查 |
| `Restarting (1)` | 在反复重启 | 看日志找原因 |
| `Exit 0` | 正常停止 | `docker compose start 容器名` |
| `Exit 1` | 异常退出 | 看日志排查 |

## 容器管理

### 启动 / 停止 / 重启

```bash
# 启动所有服务
docker compose up -d

# 暂停（容器保留，数据不丢）
docker compose stop

# 恢复暂停的容器
docker compose start

# 重启单个服务（比如 backend 卡住了）
docker compose restart backend

# 完全下线（删容器，但 volume 数据保留）
docker compose down

# 重新上线（删了容器后重新创建）
docker compose up -d
```

> `up -d` 和 `start` 的区别：`up` 会检查配置是否变化，按需重建容器；`start` 只启动已存在的容器。

### 查看日志

```bash
# 所有服务的日志（实时滚动）
docker compose logs -f

# 只看最新 100 行
docker compose logs -f --tail=100

# 只看某个服务
docker compose logs --tail=50 backend
docker compose logs --tail=50 db
docker compose logs --tail=50 frontend

# 保存日志到文件
docker compose logs --tail=1000 > /tmp/erpnext-logs.txt
```

### 进入容器内部

```bash
# 进入 backend 容器（最常用，执行 bench 命令）
docker compose exec backend bash

# 进入后可以执行 bench 命令
bench --site erpnext.example.com doctor
bench --site erpnext.example.com migrate

# 退出容器
exit
```

## 升级

### 前置条件：配置 Docker 代理

在中国大陆无法直接拉取 Docker Hub 镜像，必须先配置代理：

```bash
# 检查能否拉取镜像
docker pull frappe/erpnext:v16.21.0

# 如果超时或连接失败，需要先配置代理
# 详见 docs/04-网络代理配置.md
```

### 升级 ERPNext 版本

#### 方式 A：保留数据（小版本升级）

适用于 v16.19.1 → v16.21.0 等同一大版本内的升级：

```bash
# 1. 先备份（非常重要！）
mkdir -p ~/erpnext/backups/$(date +%F)
docker compose exec -T backend bench --site 你的站点 backup --with-files

# 2. 修改版本号
cd ~/erpnext
vim .env
# 找到 ERPNEXT_VERSION=v16.19.1，改成新版本号

# 3. 拉取新版本镜像
docker compose pull

# 4. 重建容器
docker compose up -d

# 5. 数据库迁移（必须做！）
docker compose exec backend bench migrate

# 6. 清缓存
docker compose exec backend bench clear-cache

# 7. 验证
docker compose exec backend bench --site 你的站点 doctor
```

#### 方式 B：全新安装（大版本升级/不需要保留数据）

适用于跨大版本升级，或者数据不重要、想要干净环境的情况：

```bash
# 1. 备份站点配置（如果需要）
cp .env ~/backup-env-$(date +%F)

# 2. 修改版本号
cd ~/erpnext
vim .env
# 改 ERPNEXT_VERSION 为目标版本

# 3. 停止并删除旧容器和全部数据卷
docker compose down -v

# 4. 启动新容器
docker compose up -d

# 5. 创建新站点
docker compose run --rm backend bench new-site \
  你的域名 --db-host db --db-port 3306 \
  --mariadb-root-password 你的数据库密码 \
  --admin-password admin

# 6. 安装 ERPNext
docker compose run --rm backend bench \
  --site 你的域名 install-app erpnext
```

> **注意**：`docker compose run` 创建的临时容器 IP 可能和正式 backend 容器不同，导致数据库权限问题。如果创建站点后访问返回 500 且日志报 `Access denied`，参考下文故障处理。

> **升级原则**：
> - 不要跨大版本（比如 v13 → v16），否则数据库迁移可能失败
> - 升级前必须备份
> - 升级后观察半小时，确认所有功能正常

### 升级系统（Linux）

```bash
apt update && apt upgrade -y

# 如果内核更新了，需要重启
reboot

# 重启后检查 Docker 和 ERPNext 自动恢复情况
docker ps
```

## 故障处理

### 问题：容器反复重启

```bash
# 查看日志
docker compose logs --tail=50 [容器名]
```

**常见原因和解决：**

**① AppArmor 错误**
```
apparmor profile: no such file or directory
```
→ 需要添加 LXC 适配。参考 README 中的 "PVE LXC 适配" 章节。

**② 端口被占用**
```
port is already allocated
```
→ 80 端口被其他程序用了：
```bash
ss -tlnp | grep 80
```
找到占用端口的程序，关掉它或修改 `.env` 中的 `HTTP_PUBLISH_PORT`。

**③ 数据库连接失败**
```
Can't connect to MySQL server on 'db' (113)
```
→ 数据库还没启动好，或者密码不匹配：
```bash
# 检查数据库状态
docker compose ps db
docker compose logs --tail=20 db

# 重启数据库
docker compose restart db
```

**④ 内存不足被系统杀掉**
```
Exit code 137 或 139
```
→ 容器用了太多内存，被系统 OOM killer 杀了：
```bash
# 查看内存使用
free -h
docker stats --no-stream
```
解决：降低 Gunicorn worker 数，或给服务器加内存。

### 问题：网页打不开

**情况 1：完全无法连接**

```
无法访问此网站 / 连接超时
```
→ 防火墙或安全组没开端口：
```bash
# 检查端口监听
ss -tlnp | grep 80

# 检查防火墙
iptables -L -n | grep 80
```

**情况 2：返回 502 Bad Gateway**

```
502 Bad Gateway
```
→ backend 没启动好：
```bash
docker compose ps backend
docker compose logs --tail=20 backend
docker compose restart backend
```

**情况 3：返回 404**

→ 站点配置不对：
```bash
docker compose exec backend bench --site erpnext.example.com doctor
```

**情况 4：返回 503**

```
503 Service Temporarily Unavailable
```
→ 维护模式开启了：
```bash
docker compose exec backend bench --site erpnext.example.com set-maintenance-mode off
```

**情况 5：返回 500，日志报 `Access denied for user`**

```
MySQLdb.OperationalError: (1045, "Access denied for user '_xxxxxx'@'172.18.0.5'")
```

→ 数据库用户只允许从特定 IP 连接，但 backend 容器的 IP 不匹配。

**原因**：`docker compose run --rm backend bench new-site` 创建的临时容器 IP（如 `172.18.0.11`）被写入数据库权限，但正式 backend 容器是另一个 IP（如 `172.18.0.5`）。

**解决方法一：给数据库用户添加 backend 容器 IP 的权限**

```bash
# 1. 查看 site_config.json 中的数据库用户名和密码
docker compose exec backend cat sites/你的域名/site_config.json

# 2. 创建用户并授权（允许 backend 容器 IP）
DB_USER=$(docker compose exec backend bash -c 'python3 -c "import json; print(json.load(open(\"sites/你的域名/site_config.json\"))[\"db_user\"])"')
DB_PASS=$(docker compose exec backend bash -c 'python3 -c "import json; print(json.load(open(\"sites/你的域名/site_config.json\"))[\"db_password\"])"')
DB_NAME=$(docker compose exec backend bash -c 'python3 -c "import json; print(json.load(open(\"sites/你的域名/site_config.json\"))[\"db_name\"])"')

docker compose exec -T db mariadb -u root -p$DB_PASSWORD << SQL
CREATE USER IF NOT EXISTS '${DB_USER}'@'172.18.0.5'
  IDENTIFIED BY '${DB_PASS}';
GRANT ALL PRIVILEGES ON \`${DB_NAME}\`.*
  TO '${DB_USER}'@'172.18.0.5';
FLUSH PRIVILEGES;
SQL
```

**解决方法二（推荐）：创建站点后直接授权 `%` 通配符**

这样无论容器 IP 怎么变都能连接：

```bash
docker compose exec -T db mariadb -u root -p$DB_PASSWORD << SQL
GRANT ALL PRIVILEGES ON \`数据库名\`.* TO '数据库用户'@'%';
FLUSH PRIVILEGES;
SQL
```

### 问题：ERPNext 页面加载慢

```bash
# 1. 查看是否有慢查询
docker compose exec db bash -c "tail -50 /var/log/mysql/slow.log" 2>/dev/null

# 2. 检查内存是否不足
free -h

# 3. 检查 Gunicorn worker 是否够用
docker compose logs --tail=20 backend | grep -i timeout

# 如果有大量 timeout，增加 worker 数
```

### 问题：磁盘空间报警

```bash
# 先看哪些目录大
du -sh /* 2>/dev/null | sort -rh | head -10

# 清理 Docker 日志
sudo journalctl --vacuum-time=3d

# 清理 Docker 无用资源
docker system prune -f

# 清理旧备份（保留最近 3 天）
find ~/erpnext/backups -maxdepth 1 -type d -mtime +3 -exec rm -rf {} \;

# 查看 Docker 占用
docker system df
```

### 问题：备份失败

```bash
# 查看备份日志
tail -50 ~/erpnext/logs/backup.log

# 手动执行看详细输出
bash ~/erpnext/backup.sh

# 常见原因：
df -h         # 磁盘满了？
docker compose ps  # backend 容器没启动？
```

## 日常运维清单

### 每天（2 分钟）

```bash
# 1. 看容器状态
docker compose ps

# 2. 看磁盘
df -h /

# 3. 看昨晚备份
tail -3 ~/erpnext/logs/backup.log
ls -lt ~/erpnext/backups/ | head -3
```

### 每周（5 分钟）

```bash
# 1. 看慢查询
docker compose exec db bash -c "tail -20 /var/log/mysql/slow.log"

# 2. 看容器重启次数
docker inspect $(docker ps -q) --format='{{.Name}} {{.RestartCount}}' | sort

# 3. 随机抽查一个备份文件是否能正常解压
tar -tzf ~/erpnext/backups/$(ls -t ~/erpnext/backups/ | head -1)/sites-config.tar.gz | head -10
```

### 每月（10 分钟）

- 检查是否需要升级 ERPNext 或 Docker 版本
- 检查资源配置是否还够用（数据量大了之后内存可能需要增加）
- 做一次备份恢复演练（能在测试环境正常恢复）

## 维护窗口操作指南

有些操作会影响服务，建议在维护窗口执行：

```bash
# 1. 提前通知用户
# 2. 执行备份
bash ~/erpnext/backup.sh

# 3. 关停服务
cd ~/erpnext/frappe_docker
docker compose down

# 4. 执行维护操作（升级/重启/改配置）

# 5. 启动服务
docker compose up -d

# 6. 验证
docker compose ps
docker compose exec backend bench --site erpnext.example.com doctor
curl -s -o /dev/null -w "%{http_code}" http://localhost/

# 7. 通知用户恢复
```
