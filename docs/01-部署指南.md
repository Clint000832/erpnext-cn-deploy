# 部署指南

> 从零开始部署 ERPNext 生产环境。如果你是完全新手，建议先看 README 中的"先搞懂几个概念"部分。

---

## 环境准备（第一次用 Linux 的话）

### 连接服务器

```bash
# Windows 用户用 PuTTY 或 PowerShell
# Mac/Linux 用户用终端
ssh root@你的服务器IP
```

### 更新系统

```bash
apt update && apt upgrade -y
```

### 安装 Docker

Docker 是运行 ERPNext 的基础环境。一条命令安装：

```bash
curl -fsSL https://get.docker.com | bash
```

这条命令的意思是：
- `curl`：下载工具
- `-fsSL`：静默模式，只显示必要信息
- `get.docker.com`：Docker 官方安装脚本
- `| bash`：把下载的脚本交给 bash 执行

安装完成后：

```bash
# 允许当前用户执行 docker（避免每次输入 sudo）
sudo usermod -aG docker $USER
```

> ⚠️ **重要**：执行后退出 SSH 重新登录，否则 docker 命令会提示权限不足。

### 验证安装

```bash
docker --version
# 应该显示：Docker version 24.x.x 或更高

docker compose version
# 应该显示：Docker Compose version v2.x.x
```

## 完整部署流程

### 第一步：获取项目代码

```bash
# 创建工作目录（所有 ERPNext 相关文件放这里）
mkdir -p ~/erpnext

# 进入目录
cd ~/erpnext

# 从 GitHub 下载 frappe_docker（官方 Docker 部署方案）
git clone https://github.com/frappe/frappe_docker.git

# 进入 frappe_docker 目录
cd frappe_docker
```

> 📌 `git clone` 会把整个项目从 GitHub 下载到本地。

### 第二步：配置环境变量

```bash
# 复制官方提供的模板文件
cp example.env .env
```

`example.env` 是官方提供的示例文件。`cp` 复制出一份叫 `.env` 的，这个 `.env` 就是 docker compose 实际读取的配置文件。

编辑 `.env`：

```bash
nano .env
```

找到并修改以下内容（nano 编辑器中用方向键移动光标，改完按 Ctrl+X，然后 Y，然后回车）：

```env
# ─── 以下两个密码必须修改 ───
DB_PASSWORD=你的数据库密码        # 数据库 root 密码，请用强密码
ADMIN_PASSWORD=你的管理员密码      # ERPNext 管理员密码

# ─── 以下按实际情况修改 ───
SITE_NAME=erpnext.example.com      # 站点名，可以用域名或任意名字
FRAPPE_SITE_NAME_HEADER=erpnext.example.com  # 默认站点
TZ=Asia/Shanghai                   # 时区，中国就用这个

# ─── 以下是性能相关，新手先不动 ───
GUNICORN_WORKERS=4
GUNICORN_THREADS=4
```

### 第三步：配置数据库调优

MariaDB 默认配置比较保守，我们需要优化一下。

```bash
# 回到项目根目录
cd ~/erpnext

# 创建 MariaDB 配置目录
mkdir -p mariadb-conf
```

创建配置文件：

```bash
nano mariadb-conf/tuning.cnf
```

粘贴以下内容：

```ini
[mariadb]
innodb_buffer_pool_size=3G
max_connections=200
thread_cache_size=8
slow_query_log=1
long_query_time=1
innodb_log_file_size=512M
innodb_flush_log_at_trx_commit=2
innodb_flush_method=O_DIRECT
tmp_table_size=64M
max_heap_table_size=64M
```

### 第四步：LXC 适配（判断是否需要）

```bash
cat /sys/kernel/security/apparmor/enabled
```

三种情况：

| 结果 | 含义 | 操作 |
|------|------|------|
| 显示 `1` | AppArmor 正常工作 | 跳过此步 |
| 显示 `0` | AppArmor 被禁用 | **必须做适配** |
| 显示 `No such file or directory` | 没有 AppArmor | **必须做适配** |

**如果需要适配**，创建 `~/erpnext/frappe_docker/overrides/compose.lxc.yaml`：

```bash
nano ~/erpnext/frappe_docker/overrides/compose.lxc.yaml
```

然后打开 `~/erpnext/frappe_docker/.env`，在末尾添加：

```env
COMPOSE_FILE=compose.yaml:overrides/compose.mariadb.yaml:overrides/compose.redis.yaml:overrides/compose.noproxy.yaml:overrides/compose.lxc.yaml
```

### 第五步：启动所有服务

```bash
cd ~/erpnext/frappe_docker

# 启动（-d 表示后台运行）
docker compose up -d
```

第一次执行会下载镜像，输出类似：

```
[+] Running 11/11
 ✔ frappe_docker Pulled                ← 下载镜像完成
 ✔ Container erpnext-db-1 Started      ← 数据库容器启动
 ✔ Container erpnext-redis-cache-1 Started
 ✔ Container erpnext-redis-queue-1 Started
 ✔ Container erpnext-frontend-1 Started
 ✔ Container erpnext-backend-1 Started
 ...
```

> **如果这里报错**（比如 AppArmor 错误），检查第四步是否配置正确。

启动后耐心等待 1-2 分钟，让数据库完成初始化。

```bash
# 查看所有容器状态
docker compose ps
```

所有容器都应该是 `Up` 状态。如果有 `Exit` 或 `Restarting` 的：

```bash
# 查看具体容器的日志排查
docker compose logs --tail=50 容器名
# 例如：docker compose logs --tail=50 db
```

### 第六步：创建站点

"站点"就是一套独立的 ERP 实例。

```bash
cd ~/erpnext/frappe_docker

docker compose exec backend \
  bench new-site erpnext.example.com \
  --admin-password "你的管理员密码" \
  --db-root-password "你的数据库密码"
```

这条命令分解：

| 部分 | 说明 |
|------|------|
| `docker compose exec backend` | 进入正在运行的 backend 容器 |
| `bench new-site` | 用 bench 工具创建新站点 |
| `erpnext.example.com` | 站点名称 |
| `--admin-password` | 设置管理员（Administrator）密码 |
| `--db-root-password` | 使用 root 身份连接数据库 |

如果成功，会显示 `Site erpnext.example.com has been created`。

**如果失败**，最常见的原因是数据库还没初始化好，等一分钟再试。

### 第七步：安装 ERPNext 应用

创建站点后，站点是空的。需要安装 ERPNext 应用才有功能。

```bash
# 安装 ERPNext（最耗时的步骤，5-10 分钟）
docker compose exec backend bench --site erpnext.example.com install-app erpnext
```

这条命令会做：
1. 下载 ERPNext 依赖的 Python 包
2. 安装所有模块（财务、销售、库存、HR...）
3. 创建数据库表
4. 初始化系统数据

等待过程中不要中断，可以去做别的事。

安装完成后：

```bash
# 数据库迁移（确保表结构最新）
docker compose exec backend bench --site erpnext.example.com migrate

# 清理缓存
docker compose exec backend bench --site erpnext.example.com clear-cache

# 健康检查
docker compose exec backend bench --site erpnext.example.com doctor
```

`doctor` 会检查系统状态。如果没有 ERROR 级别的报错，就说明安装成功。

### 第八步：验收

```bash
# 命令行检查
curl -s -o /dev/null -w "HTTP状态码: %{http_code}\n" http://localhost/
# 正常应该返回 200 或 302
```

打开浏览器，访问：

```
http://你的服务器IP/login
```

输入：
- 用户名：`Administrator`
- 密码：你设置的管理员密码

如果一切正常，会看到 ERPNext 的主界面。👏

## 后续配置

### 配置备份

```bash
# 复制本仓库的备份脚本
cp ~/erpnext-deploy/scripts/backup.sh ~/erpnext/backup.sh

# 创建日志目录
mkdir -p ~/erpnext/logs

# 测试备份
bash ~/erpnext/backup.sh

# 配置每天自动备份（凌晨 2 点）
echo '0 2 * * * root /root/erpnext/backup.sh > /root/erpnext/logs/backup.log 2>&1' \
  | sudo tee /etc/cron.d/erpnext
```

### 配置日志轮转

防止 Docker 日志撑爆磁盘：

```bash
sudo tee /etc/docker/daemon.json << 'EOF'
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "50m",
    "max-file": "3"
  }
}
EOF

sudo systemctl restart docker
```

> ⚠️ 重启 Docker 会让所有容器重启，建议在维护窗口执行。

### 配置容器资源限制

参考本仓库的 `config/compose.lxc.yaml`，可以根据你的服务器配置调整 CPU 和内存限制。

## 各步骤常见问题

### 第五步（docker compose up -d）失败

```
Error response from daemon: unable to apply apparmor profile
```
→ 检查 LXC 适配（第四步）是否做了。

```
port is already allocated
```
→ 80 端口被占用。改 `.env` 中的 `HTTP_PUBLISH_PORT=8080`。

```
Cannot connect to the Docker daemon
```
→ Docker 没有启动。执行 `systemctl start docker`。

### 第六步（创建站点）失败

```
Can't connect to MySQL server on 'db'
```
→ 数据库还没有准备好。等 1-2 分钟再试。

```
socket.gaierror: [Errno -2] Name or service not known
```
→ backend 容器无法解析 `db` 主机名。重启容器：
```bash
docker compose restart backend
```

### 第七步（install-app）失败

```
ModuleNotFoundError: No module named '...'
```
→ 网络问题导致依赖下载失败，重试即可。

安装中途断网或超时：
```bash
# 重试安装
docker compose exec backend bench --site erpnext.example.com install-app erpnext
```
